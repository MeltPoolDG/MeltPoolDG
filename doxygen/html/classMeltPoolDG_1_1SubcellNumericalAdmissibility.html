Detailed Description

template<int dim, int n_components, typename number>
class MeltPoolDG::SubcellNumericalAdmissibility< dim, n_components, number >

This class provides an alternative to the CellwiseNumericalAdmissibility class, which itself is only able to detect oscillations across DG cells, but not oscillations within a single DG cell that stay within the range of the old solution over the cell and its face neighbors. The SubcellNumericalAdmissibility class is able to detect oscillations within a single DG cell by checking the candidate solution on each subcell against the relaxed extrema of the old solution on the subcell itself and its face neighbors as discussed by Vilar [1]. Within the cell, these are the adjacent subcells. Across a face of the cell, the neighboring cell contributes the extrema of the old solution over its layer of subcells at this face, i.e., not only the subcell directly opposite. Note that this differs from the original formulation by Vilar, who only uses the subcell directly opposite to the face.

Since the bounds of each subcell are contained in the bounds of the cellwise check, the SubcellNumericalAdmissibility class is stricter than the CellwiseNumericalAdmissibility class: every cell rejected by the cellwise check is also rejected here. Hence, using both classes together gives the same result as using the SubcellNumericalAdmissibility class alone. Note that for stability it usually is enough to only use the CellwiseNumericalAdmissibility class, since this effectively prevents oscillations from propagating across DG cells. However, if it is of interest to also detect oscillations within a single DG cell, the SubcellNumericalAdmissibility class should be used instead. This, however, comes at the price of potentially more cells being marked as troubled.

The usage of the class is the same as for the CellwiseNumericalAdmissibility class: call submit_cell() for every locally owned cell batch and submit_ghost_cell() for every ghost cell batch, and then evaluate(). Since neighbors can only widen the bounds, submit_cell() already decides most subcells using only the subcells of their own cell: a subcell that passes is admissible, and a subcell in the interior of the cell that fails is not. Only failing subcells at the boundary of the cell are stored and decided in evaluate(), once the face layer extrema of all neighboring cells, including the ghost cells, are available. The evaluate() function combines the result with the given vector of bitsets by a logical AND operation.

[1] F. Vilar, A posteriori correction of high-order discontinuous Galerkin scheme through subcell finite volume formulation and flux reconstruction, J. Comput. Phys. 387, 2019.

◆ evaluate()

template<int dim, int n_components, typename number >
void MeltPoolDG::SubcellNumericalAdmissibility< dim, n_components, number >::evaluate ( std::vector< MaskType > &  troubled_cells_mask)

Decide the subcells deferred by submit_cell() using the face layer extrema of the neighboring cells, and compute the admissibility of the candidate solution for each locally owned cell batch.

Parameters
troubled_cells_maskA vector of bitsets, where each bitset corresponds to a locally owned cell batch and each bit to a vectorization lane. The bits of the inadmissible lanes are set, while all other bits are kept, i.e., the result is combined with the existing bits by a logical OR. It is assumed that the given vector already has the correct size.

Check the candidate on all subcells of the given cell batch against the bounds from the subcells of the same cell, and compute the face layer extrema of the old solution needed by the neighboring cells. Subcells at the boundary of the cell that fail this check are stored and decided in evaluate(), since the face layer extrema of the neighboring cells may widen their bounds.

Parameters
cell_batchThe index of the locally owned cell batch.
phi_oldThe FESubcellEvaluation object containing the old solution evaluated on the cell batch.
phi_candidateThe FESubcellEvaluation object containing the candidate solution evaluated on the cell batch.

For each locally owned cell batch, a bitset indicating which vectorization lanes are admissible according to the relaxed discrete maximum principle criterion. The bits are set to 1 for admissible lanes and 0 for inadmissible lanes. Lanes with deferred subcells are only final after evaluate().
